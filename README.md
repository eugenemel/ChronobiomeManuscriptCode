# Code for Chronobiome Analysis of UK Biobank Data

## Manuscript Title:
###  Disrupted Daytime Variation in Circulating Factors as a Predictor of Disease and Mortality
### medRxiv 2026.01.16.26344298; doi: https://doi.org/10.64898/2026.01.16.26344298


### Notebook and Code Structure

1. SPEC.md                    - UK Biobank fields used and R package versions
2. preprocess_UKBB.Rmd        - Builds the preprocessed UKBB data files (needs UKBB access)
3. ChronobiomeUKBB.Rmd        - Main Notebook for UK Biobank data
4. ChronobiomeSerialOlink.Rmd - Comparison with serial Olink data
5. ChronoFunctions.R          - Support functions

### Folder Structure

    preprocessed/          - Individual-level UKBB data [ not included in the repository ]
    outputs/               - Checkpoints (.Rds, .Rdata) and other output files generated by the analysis
    figures/               - Figures generated by the analysis
    support_files/         - ICD-10 code titles and the serial-sampling Olink study [ its individual-level files are not included in the repository ]


## How to Run

### Requirements

- **R 4.4.1 and the packages listed in [SPEC.md](SPEC.md).** SPEC.md includes a snippet that installs the exact versions used.

- **UK Biobank data access.** [SPEC.md](SPEC.md) section 2 lists the fields used.

### 1. Preprocess UK Biobank

`preprocess_UKBB.Rmd` builds the data tables in `preprocessed/` from the record-level data and the hospital and death tables. The one input made outside this repository is the Olink protein file `PPP_PLATE_ADJUSTED_IMPUTE1_3K.Rds` (SPEC.md section 2.3 describes how). SPEC.md section 2.1 lists every input file and its UKB fields. Individual-level data are not included in this repository.


### 2. Main analysis: `ChronobiomeUKBB.Rmd`

1. **First time only:** run sections 1 to 4.1. They load the inputs, build the model dataframe `X`, z-scale the biomarkers and save `outputs/savedX.Rdata`.
2. **Every session:** start at section 4.2 ("restart here"), which reloads `X` from that checkpoint. Then run section 5, which loads the functions and event data that every later section needs.
3. **Analyses:** run the sections you need. Each section that fits models saves its results to `outputs/`, and the plotting section after it reads them back, so figures can be redrawn without refitting. Figures are written to `figures/`.

The YAML header has two parameters:

- `instance` picks the visit: 0 = baseline (default), 1 = repeat assessment, 2 = first imaging visit. Checkpoints for visits 1 and 2 get an `_instanceN` suffix, so they do not overwrite the baseline ones.
- `censor_date` (default 2023-09-01, the latest event date in the data) ends follow-up: participants without an event are censored at this date or at death.

### 3. Serial-sampling comparison: `ChronobiomeSerialOlink.Rmd`

This notebook needs two baseline checkpoints from the main notebook: `outputs/savedX.Rdata` (section 4.1) and `outputs/saveOBSERVED.Rds` (section 7).

It also reads three files from the serial-sampling Olink study (the Chronobiome study) in `support_files/`:

- `2025-09-17_Common-chronobiome-and-ukbb-cyclers_Sample-metadata_AB-proteomics_Plasma_NPX-values.txt` (sample metadata) and `2025-09-17_All-protein-assays_Feature-matrix_AB-proteomics_Plasma_NPX-values.txt` (NPX values). These are subject-level data and are not included in the repository; they can be requested from the corresponding authors of the Chronobiome study.
- `Cosinor-lmer_Fit-across-all-samples_Olink_Plasma_Proteomics.txt`: the cosinor fit of each protein in the serial study. This summary file is included. The main notebook also reads it, for the mortality model (section 13.4) and the comparison in section 14.9.
